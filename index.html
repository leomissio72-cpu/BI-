Modelagem de Dados — Star Schema

O modelo dimensional correto é a base de qualquer solução BI de alto desempenho. Star Schema é o padrão ouro.

⚠️ Regra nº 1
Nunca construa visuais sem um modelo de dados bem estruturado. Um modelo ruim gera DAX complexo, lento e incorreto.

Star Schema: Fato + Dimensões

TABELA FATO
fVendas / fAtendimentos / fFinanceiro
Contém as métricas e eventos do negócio (quantidades, valores, datas).

✅ Chaves estrangeiras (FK) para dimensões
✅ Colunas numéricas (valor, qtd, duração)
✅ Granularidade baixa (uma linha = um evento)
❌ Sem textos descritivos (mova para dimensões)
❌ Sem colunas calculadas desnecessárias
TABELA DIMENSÃO
dCliente / dProduto / dCalendario / dFilial
Contém os atributos descritivos para filtrar e agrupar.

✅ Chave primária (PK) única
✅ Atributos de texto (nome, categoria, tipo)
✅ Hierarquias (Ano → Mês → Dia)
✅ Tabela pequena (poucas linhas, muitas colunas)
❌ Sem relações entre dimensões

Tabela de Calendário (obrigatória!)

✅ Boa prática
Toda solução Power BI precisa de uma tabela dCalendario contínua, marcada como Tabela de Datas, cobrindo todo o intervalo da tabela Fato.
DAX — dCalendario 
-- Cria tabela de datas completa com DAX
dCalendario =
VAR DataInicial = DATE(2020, 1, 1)
VAR DataFinal   = DATE(2025, 12, 31)
RETURN
ADDCOLUMNS(
    CALENDAR(DataInicial, DataFinal),
    "DateKey",      INT(FORMAT([Date], "YYYYMMDD")),
    "Ano",           YEAR([Date]),
    "MesNum",        MONTH([Date]),
    "NomeMes",       FORMAT([Date], "mmm"),
    "AnoMes",        FORMAT([Date], "YYYY-MM"),
    "AnoMesNum",     YEAR([Date]) * 100 + MONTH([Date]),
    "Trimestre",     "T" & INT((MONTH([Date]) + 2) / 3),
    "Semana",        WEEKNUM([Date], 2),
    "DiaDaSemana",   WEEKDAY([Date], 2),
    "NomeDia",       FORMAT([Date], "dddd"),
    "EhDiaUtil",     IF(WEEKDAY([Date], 2) <= 5, 1, 0),
    "EhHoje",        IF([Date] = TODAY(), 1, 0)
)

Tipos de Relações

TipoCardinalidadeDireção do FiltroUso recomendado
⭐ Padrão1:N (Dimensão → Fato)ÚnicaStar Schema clássico — use sempre que possível
🔄 Bidirecional1:N ou N:NAmbasApenas quando necessário — impacto na performance
⚠️ N:NMuitos para muitosÚnica ou bidirecionalEvitar; use tabela de bridge quando necessário
🔒 InativoQualquerNenhuma (manual)Múltiplas datas — ativar com USERELATIONSHIP()

Antipadrões a Evitar

Modelos com uma única tabela gigante tornam DAX impossível, criam ambiguidades e não aproveitam o motor VertiPaq. Normalize seus dados em Fato + Dimensões separados.
Colunas calculadas são armazenadas fisicamente no modelo — aumentam o tamanho do .pbix e são processadas na atualização. Use medidas sempre que possível para cálculos dinâmicos.
Relações bidirecionais podem criar loops de filtro e resultados inesperados. Use CROSSFILTER() ou USERELATIONSHIP() dentro de medidas DAX para controle preciso.
As funções de Time Intelligence do DAX (SAMEPERIODLASTYEAR, TOTALYTD etc.) exigem uma tabela de datas marcada como "Tabela de Datas" com datas contínuas e sem lacunas.

DAX — Fundamentos Essenciais

Data Analysis Expressions: linguagem funcional baseada em contexto de linha e contexto de filtro.

MEDIDA (Measure)
Calculada dinamicamente conforme o contexto do visual. Não ocupa espaço no modelo. É a abordagem preferida para KPIs.

Total Vendas := SUM(fVendas[Valor])
COLUNA CALCULADA
Avaliada linha a linha na carga de dados. Armazenada fisicamente. Use apenas quando precisar do valor para filtrar/agrupar (ex: faixa de preço).

Categoria Valor = IF([Valor]>1000,"Alto","Baixo")

Medidas Fundamentais

DAX — Agregações básicas
-- Soma simples
Total Vendas := SUM(fVendas[Valor])

-- Contagem de linhas com filtro
Qtd Pedidos := COUNTROWS(fVendas)

-- Contagem de valores únicos
Qtd Clientes Únicos := DISTINCTCOUNT(fVendas[ClienteID])

-- Ticket médio com tratamento de divisão por zero
Ticket Médio := DIVIDE([Total Vendas], [Qtd Pedidos], 0)

-- Máximo e mínimo
Maior Venda  := MAX(fVendas[Valor])
Menor Venda  := MIN(fVendas[Valor])

-- Média com AVERAGEX para lógica personalizada
Média por Cliente :=
AVERAGEX(
    SUMMARIZE(fVendas, fVendas[ClienteID]),
    [Total Vendas]
)

Contexto de Filtro vs Contexto de Linha

🧠 Conceito Fundamental
Contexto de Filtro: conjunto de filtros aplicados por slicers, visuais e relações. Medidas são avaliadas nesse contexto.
Contexto de Linha: linha atual sendo processada em uma iteração (SUMX, AVERAGEX, etc.). Contexto de linha NÃO propaga filtros automaticamente — use RELATED() para isso.
DAX — Contexto e iteração
-- SUMX: itera linha a linha na tabela
Total com Desconto :=
SUMX(
    fVendas,
    fVendas[Quantidade] * fVendas[PrecoUnitario] * (1 - fVendas[Desconto])
)

-- RELATED: acessa coluna de tabela relacionada no contexto de linha
Margem Bruta :=
SUMX(
    fVendas,
    fVendas[Valor] - RELATED(dProduto[CustoUnitario]) * fVendas[Quantidade]
)

-- % sobre total (contexto removido com ALL)
% Participação Vendas :=
DIVIDE(
    [Total Vendas],
    CALCULATE([Total Vendas], ALL(dProduto)),
    0
)

Funções Lógicas e de Texto

DAX — IF, SWITCH, FORMAT
-- IF simples
Status Meta :=
IF([Total Vendas] >= [Meta], "✅ Atingiu", "❌ Abaixo")

-- SWITCH para múltiplas condições (mais eficiente que IF aninhado)
Faixa de Desempenho :=
SWITCH(
    TRUE(),
    [% Atingimento] >= 1.00, "🟢 Excelente",
    [% Atingimento] >= 0.80, "🟡 Bom",
    [% Atingimento] >= 0.60, "🟠 Regular",
    "🔴 Crítico"
)

-- FORMAT para exibição
Receita Formatada :=
FORMAT([Total Vendas], "R$ #,##0.00")

-- COALESCE: retorna primeiro valor não vazio (substituindo IF + ISBLANK)
Nome Cliente Seguro :=
COALESCE(MAX(dCliente[NomeCompleto]), "Não Identificado")

DAX Avançado — CALCULATE, Time Intelligence e Filtros

CALCULATE é a função mais poderosa do DAX. Dominar seu comportamento é dominar o Power BI.

CALCULATE — Modificando o Contexto

⚡ Regra de Ouro
CALCULATE transforma contexto de linha em contexto de filtro AND sobrescreve/adiciona filtros. Cada argumento depois da expressão é um modificador de filtro.
DAX — CALCULATE e modificadores
-- Vendas apenas da categoria "Eletrônicos"
Vendas Eletrônicos :=
CALCULATE(
    [Total Vendas],
    dProduto[Categoria] = "Eletrônicos"
)

-- ALL: remove todos os filtros de uma tabela/coluna
Total Geral Vendas :=
CALCULATE([Total Vendas], ALL(dProduto))

-- ALLEXCEPT: mantém apenas os filtros especificados
Vendas Região Total :=
CALCULATE([Total Vendas], ALLEXCEPT(dFilial, dFilial[Região]))

-- KEEPFILTERS: adiciona sem sobrescrever o filtro existente
Vendas SP Restrito :=
CALCULATE(
    [Total Vendas],
    KEEPFILTERS(dFilial[UF] = "SP")
)

-- REMOVEFILTERS (alias de ALL, mais legível)
Vendas Sem Filtro Data :=
CALCULATE([Total Vendas], REMOVEFILTERS(dCalendario))

Time Intelligence — Análise Temporal

DAX — Time Intelligence completo
-- YTD: acumulado do ano até a data selecionada
Vendas YTD :=
TOTALYTD([Total Vendas], dCalendario[Date])

-- MTD: acumulado do mês até hoje
Vendas MTD :=
TOTALMTD([Total Vendas], dCalendario[Date])

-- Mesmo período do ano anterior (LY)
Vendas LY :=
CALCULATE([Total Vendas], SAMEPERIODLASTYEAR(dCalendario[Date]))

-- Variação YoY em %
Crescimento YoY % :=
DIVIDE([Total Vendas] - [Vendas LY], [Vendas LY], 0)

-- MoM: comparação com mês anterior
Vendas Mês Anterior :=
CALCULATE([Total Vendas], PREVIOUSMONTH(dCalendario[Date]))

-- Rolling 3 meses (últimos 90 dias)
Vendas Rolling 3M :=
CALCULATE(
    [Total Vendas],
    DATESINPERIOD(dCalendario[Date], LASTDATE(dCalendario[Date]), -3, MONTH)
)

-- YTD do ano anterior (para comparação YTD vs LY YTD)
Vendas LY YTD :=
CALCULATE(
    TOTALYTD([Total Vendas], dCalendario[Date]),
    SAMEPERIODLASTYEAR(dCalendario[Date])
)

Ranking e Classificação

DAX — RANKX e TOP N
-- Rank de produto por vendas (1 = maior)
Rank Produto :=
RANKX(
    ALL(dProduto[NomeProduto]),
    [Total Vendas],
    ,
    DESC,
    DENSE
)

-- Flag: é TOP 5?
É Top 5 :=
IF([Rank Produto] <= 5, "⭐ Top 5", "Outros")

-- Percentil 80 (Pareto / análise ABC)
Vendas Acumuladas % :=
VAR RankAtual = [Rank Produto]
RETURN
DIVIDE(
    SUMX(
        FILTER(ALL(dProduto), [Rank Produto] <= RankAtual),
        [Total Vendas]
    ),
    CALCULATE([Total Vendas], ALL(dProduto))
)

Variáveis (VAR / RETURN) — Melhor Prática

✅ Use VAR sempre que possível
Variáveis melhoram legibilidade, evitam recálculos e facilitam debug. O DAX avalia cada VAR uma vez no contexto em que foi declarada.
DAX — VAR / RETURN avançado
Análise de Meta :=
VAR VendasAtual = [Total Vendas]
VAR VendasLY    = [Vendas LY]
VAR Meta        = VendasLY * 1.1     -- 10% acima do LY
VAR Gap         = VendasAtual - Meta
VAR GapPct      = DIVIDE(Gap, Meta, 0)
RETURN
SWITCH(
    TRUE(),
    ISBLANK(VendasLY),       "Sem histórico",
    GapPct >=  0.05,          "🟢 Superou meta",
    GapPct >=  0,             "🟡 Dentro da meta",
    GapPct >= -0.10,          "🟠 Abaixo (-10%)",
    "🔴 Crítico (> -10%)"
)

RLS — Row-Level Security

🔒 Segurança obrigatória
Nunca publique relatórios com dados sensíveis (financeiro, RH, saúde) sem RLS configurado e testado com todos os papéis.
DAX — RLS estático e dinâmico
-- RLS Estático: filtra pela coluna diretamente
-- (configurado na UI do Power BI Desktop → Gerenciar Funções)
dFilial[UF] = "SP"

-- RLS Dinâmico: usa o e-mail do usuário autenticado
-- Na tabela dUsuarios com colunas: Email, FilialID, Perfil
[Email] = USERPRINCIPALNAME()

-- Medida para verificar o papel do usuário logado
Perfil Usuário :=
VAR Email = USERPRINCIPALNAME()
RETURN
CALCULATE(
    MAX(dUsuarios[Perfil]),
    dUsuarios[Email] = Email
)
